# 图纸编辑 Agent 技术路线

日期：2026-10-16

## 1. 问题定义

一张图纸从打开到保存，构成一条会话。打开时的文档是起点 \(s_0\)，保存时的文档是终点 \(s_T\)。中间每一次生效的编辑是动作 \(a_t\)，执行后得到 \(s_t\)。

\[
s_0 \xrightarrow{a_1} s_1 \xrightarrow{a_2} \cdots \xrightarrow{a_T} s_T
\]

\(s_T\) 是该会话的正确答案。用户做过的每一步都是合法样本。到达同一终点的其它顺序同样正确。策略要学的是：给定当前文档，选出一个动作，使若干步之后的文档与 \(s_T\) 一致。

上线时调用方只提供一张待改图纸，没有 \(s_T\)。这时策略沿用同一套动作，停止条件改为策略自己输出保存，或达到步数上限。终点是否可接受，由第 8 节的打分模型判断。

本路线的交付物是四件事：

1. 会话数据规范，以及能把事务重放到 \(s_T\) 的采集程序。
2. 无界面仿真，训练程序可以重置、执行、观察。
3. 策略：先模仿会话中的动作，再在仿真里按与 \(s_T\) 的差异继续训练。
4. 编辑服务：输入图纸，输出动作序列或改完的文档。

## 2. 范围

数据从第一天起记录图纸上的全部生效编辑，包括标注、视图、文字、图框和其它元素。映射表按元素类型和字段族登记。第一批登记的动作覆盖下列标注：

- 线性尺寸、对齐尺寸
- 直径、半径
- 引线
- 粗糙度
- 形位公差

角度尺寸、焊接符号、基准符号、图框文字、视图平移和缩放先完整落库。映射表在第 B 阶段按出现频率补齐。训练开始前，未登记动作占全部步骤的比例低于 5%。高于该比例时，先补映射，再开训练。

一张图纸上的多个视图先分开训练：状态、候选和渲染都以单个视图为范围，该视图以外的几何只作为遮挡。动作的目标或测量对象落在另一个视图时，整条会话标成跨视图，留到单视图策略达到第 E 阶段验收之后再做。

## 3. 数据

### 3.1 采集点

采集挂在编辑器的事务提交上，不改变用户的操作方式，也不另做题目。

| 时机 | 写入 |
|---|---|
| 文档打开完成 | 起点快照 |
| 一次事务提交成功 | 一步事务记录 |
| 撤销 | 从净路径弹出最近一步，该步进入撤销栈 |
| 撤销后产生新编辑 | 清空撤销栈，新编辑接到净路径末尾 |
| 用户保存 | 终点快照，会话关闭 |

净路径就是用户最后保留下来的那一串事务。被撤销且没有重做的步骤不进入训练样本。

### 3.2 会话格式

一条会话一个目录，UTF-8 JSON。`schema_version` 从 `edit-session-1` 起。

```text
session.json          会话头
s0.json               起点，整份文档序列化
steps/0001.json       第 1 步事务
steps/0002.json
sT.json               终点，整份文档序列化
actions.jsonl         由 steps 归一化得到的动作，一行一个
```

会话头：

| 字段 | 含义 |
|---|---|
| session_id | 会话标识 |
| drawing_id | 图纸标识。同一图纸的多次编辑共用此字段，用于划分数据集 |
| schema_version | 格式版本 |
| opened_at, saved_at | 打开与保存时间 |
| n_steps | 净路径上的事务数 |
| n_actions | 归一化后的动作数 |
| cross_view | 是否含跨视图动作 |
| editor_build | 编辑器版本，用于排除旧格式样本 |

一步事务与编辑器现有导出对齐，字段为：

```text
{
  "step_index": 1,
  "cmd_id": "命令标识",
  "timestamp": "",
  "added": [ "新增元素树" ],
  "deleted": [ "被删元素 id" ],
  "modified": [
    { "id": 1001, "property": "字段名", "old": "旧值", "new": "新值" }
  ]
}
```

`added` 用编辑器现有的元素树。`deleted` 是元素 id 列表。`modified` 的 `old` 与 `new` 必须是事务里的真实旧值和新值。

当前导出把 `old` 和 `new` 都写成了提交之后的当前值，旧值丢失。采集上线前要改这一处：从事务的属性变更里取真实 `old` 和 `new`，再写入 `modified`。加载仍按 `new` 写回文档，与现在的重放方式一致。

### 3.3 重放校验

每条会话在入库前自动重放一次：载入 \(s_0\)，按净路径依次应用事务，得到 \(s_T'\)。\(s_T'\) 与保存的 \(s_T\) 在元素集合和已登记字段上必须一致，差异为 0 才入库。重放失败的会话单独存放，不进入训练。

## 4. 动作

策略不直接预测属性补丁。事务先经映射表变成动作，训练、仿真和上线使用同一份映射。映射的输入是 `cmd_id`、元素类型、字段名；输出是动作名和参数。一次事务改多个字段时，按字段优先级拆成多个动作，顺序固定，保证同一事务每次得到同一串动作。

### 4.1 动作表

坐标使用图纸毫米坐标，与文档内坐标一致。

| 动作 | 适用对象 | 参数 |
|---|---|---|
| move_dim_line | 线性、对齐、直径、半径 | 目标 id，尺寸线新位置（直线用线上一点加法向偏移；圆弧尺寸用扇区中心角） |
| move_text | 全部带文字的标注 | 目标 id，文字锚点新坐标 |
| move_leader_end | 引线 | 目标 id，箭头端新坐标 |
| set_content | 全部带文字的标注 | 目标 id，字段名，新值。字段名为前缀、后缀、公差上差、公差下差、精度、替代文字 |
| create_linear | — | 被测边或两端点的几何引用，尺寸线位置，文字位置 |
| create_diameter | — | 被测圆的几何引用，扇区，文字位置 |
| create_radial | — | 被测圆弧的几何引用，扇区，文字位置 |
| create_leader | — | 落点几何引用，箭头端，文字位置，文字 |
| create_roughness | — | 附着边的几何引用，放置参数，符号参数 |
| create_gdt | — | 附着对象的几何引用，框的位置，框的内容 |
| delete | 已有标注 | 目标 id |
| save | — | 无 |

`set_content` 的字段名来自白名单。白名单外的字段保持为未识别，不塞进同一个动作里。

几何引用在会话中写成稳定描述：所属视图 id、几何类型（直线、圆、圆弧、点）、在该视图几何序列中的序号，以及用于校验的端点或圆心坐标。重放时先按序号查找，再用坐标核对；序号失效时按坐标最近邻匹配，距离超过 0.5 mm 则该步记为重放失败。

### 4.2 合并与过滤

同一目标、同一动作名、中间没有其它动作碰到该目标、且只有位置参数变化的连续动作，合并为一条。合并后的旧位置取第一下的旧值，新位置取最后一下的新值。内容修改不合并。

下列事务不产生训练动作：选择、缩放视图、相机平移、未改任何已登记字段的空事务。它们保留在 `steps/` 里，供审计，不写入 `actions.jsonl`。

映射表没有条目的事务记为 `unknown`，参数里保留 `cmd_id`、元素类型和字段名。`unknown` 不作为策略的输出类别。它的占比是映射表是否可训练的指标。

### 4.3 样本

归一化之后，第 \(t\) 个动作为一条样本：输入是执行该动作之前的文档状态，标签是该动作。一个会话产生 \(n\) 条模仿样本，外加终点文档本身，供差异计算和打分模型使用。

数据集按 `drawing_id` 划分：90% 训练，10% 验证。同一 `drawing_id` 只出现在一个划分中。验证集在第 A 阶段冻结名单，之后新增会话只进入训练，直到下一次明确扩验证集。

## 5. 状态

执行一步之后，仿真导出三样东西，作为策略的输入。

**文档表。** 当前视图内每条标注一行：id、类型、几何引用、尺寸线或符号的位置、文字锚点、文字内容、公差、精度。视图外框和零件轮廓以折线坐标附在表外。这张表是内容类动作的依据，也是差异函数的对齐依据。

**实例着色图。** 每个视图一张，分辨率 \(256 \times 256\)，无抗锯齿。背景为黑。每条可编辑标注用一种纯色填满其文字框、尺寸线和引线，颜色与 id 的对应写入图例。零件轮廓和剖面线写入另一张单通道占位图，标注像素不进入这张图。位置类动作主要依靠这两张图判断重叠、出框和贴边。

**全局向量。** 固定长度，随 `schema_version` 冻结。第一版包含：视图宽高（mm）、标注总数、各类型条数、本步序号、本步序号除以该会话动作数、常数 1。向量缺项补 0。

## 6. 差异

差异用来做三件事：入库校验、模仿阶段的回放指标、强化学习的奖励。三处使用同一函数。

### 6.1 对齐

把当前文档的标注集合 \(A\) 与终点集合 \(B\) 对齐。

1. id 相同的标注先配成一对。
2. 剩余标注按类型必须相同，再按几何引用相同配对。
3. 仍剩余的，在同类型内用位置最近配对，文字锚点距离大于 20 mm 的不配。
4. \(B\) 中未配上的计为缺失，\(A\) 中未配上的计为多余。

id 能对上时，以 id 为准，不用位置把它们拆开。策略新建的标注会得到新 id，这时走第 2、3 步。

### 6.2 分量

对每一对已对齐标注：

- 位置误差：尺寸线参考点距离与文字锚点距离之和，单位 mm。无尺寸线的符号只用文字锚点。
- 字段误差：`set_content` 白名单内每个字段不相等计 1。数值字段在 \(10^{-4}\) mm 以内视为相等。

汇总为四个数：

| 符号 | 含义 |
|---|---|
| \(P\) | 已对齐标注的位置误差之和（mm） |
| \(F\) | 字段不相等的个数 |
| \(M\) | 缺失条数 |
| \(E\) | 多余条数 |

\[
d = P / \sigma + F + M + E, \qquad \sigma = 1\,\text{mm}
\]

\(d = 0\) 当且仅当四个分量都为 0。1 mm 的位置误差与 1 个字段错误、1 条缺失、1 条多余在标量里权重相同。\(\sigma\) 若在验证集上使位置项淹没其余三项，再改 \(\sigma\)，并同时重算已记录的 \(d\)。对外报告始终给出 \((P, F, M, E)\)，不只给 \(d\)。

入库校验使用严格相等：\(d = 0\)，且不经过第 3 步的位置就近配对。就近配对只用于策略自己生成的结果。

## 7. 仿真

仿真进程内加载一份无界面文档，对外是本地调用的四个函数。训练程序与编辑器通过这四个函数交互，不通过鼠标或界面。

| 函数 | 输入 | 输出 |
|---|---|---|
| reset | 起点文档 | 第 5 节的状态 |
| step | 一个动作 | 新状态、该步是否被文档拒绝、是否已保存 |
| observe | 无 | 当前状态 |
| distance | 终点文档 | \((P, F, M, E)\) 和 \(d\) |

`step` 内部把动作反查回事务：新增写成元素树，删除写成 id，修改写成带 `new` 的属性列表，再调用现有的文档加载。几何由编辑器重算。动作引用的 id 不存在、几何引用匹配失败、或加载后文档报错，该步记为拒绝，状态保持不变。

仿真必须确定性：同一起点、同一动作序列，两次执行的文档表一致。实例着色图的颜色按标注 id 排序后分配，不随执行时机变化。

另外提供 `replay(session)`：从该会话的 \(s_0\) 依次执行 `actions.jsonl`，返回每一步的 \(d(\cdot, s_T)\)。第 C 阶段用它做回归。

步数上限取 \(\max(32,\, 2 \times \text{该会话动作数})\)。策略输出 `save` 或达到上限时回合结束。上限只作用于训练和评测里的自主走子，用户会话本身不截断。

## 8. 策略

### 8.1 候选

每一步不在整个连续空间里直接采样，而是先枚举候选，再对候选打分。

- 对当前视图内每条标注，按其类型挂上可以执行的动作：`move_dim_line`、`move_text`、`move_leader_end`、`set_content` 的各个字段、`delete`。
- 对第 4.1 节每种新建动作，为每个可测量几何引用生成一条候选。可测量对象由编辑器给出：当前视图的边、圆、圆弧、端点，带几何引用。
- 加上一条 `save`。

位置参数不放进候选枚举。候选只决定动作名、目标和字段名；位置由单独的回归头输出。内容类参数在候选里已经落到具体字段，回归头或分类头再给出新值。数值字段（公差、精度、坐标）用回归，前缀、后缀和替代文字用分类，词表来自训练集，验证集里未见过的取值记为未登录词。

候选数超过 512 时，保留 `save`、全部新建类型中几何引用最长的若干条，以及其余按文字框面积从大到小保留，直到 512。截断比例写入训练日志。验证集上若超过 10% 的步骤发生截断，把上限提高到 1024 后重训，不在截断状态下比较指标。

被文档拒绝过的同类候选，在本回合内掩掉，避免反复尝试同一非法动作。

### 8.2 网络

三路输入：实例着色图与占位图、全局向量、候选特征。候选特征包含动作名的 one-hot、标注类型、目标在图上的框、几何引用类型、字段名。卷积网络读图，与全局向量拼接后得到上下文向量；每个候选用同一上下文打出一个标量分。训练时对用户选中的那个候选做交叉熵。位置头在选中候选上做平滑 L1，词表头做交叉熵。三项损失相加，位置项系数 1，词表项系数 1，候选项系数 1。验证集上若某一项损失不下降，再单独调系数。

模仿阶段的优化器用 AdamW，学习率 \(3 \times 10^{-4}\)，批大小 32，按图纸打乱后再取步，避免一个 batch 全来自同一会话。早停看验证集回放 \(d\) 的中位数，连续 5 个评估轮不下降则停。

### 8.3 模仿之后的强化学习

模仿学到的是用户的顺序。强化学习从这份权重出发，在仿真里自己选动作。起点是验证集以外的训练图纸的 \(s_0\)，终点是对应的 \(s_T\)，奖励只依赖与 \(s_T\) 的差异和步数。

记 \(\Phi(s) = -d(s, s_T)\)，\(\gamma = 0.99\)，每步固定代价 \(c = 0.01\)。第 \(t\) 步奖励

\[
r_t = -c + \gamma \, \Phi(s_{t+1}) - \Phi(s_t)
\]

回合回报把中间的 \(\Phi\) 抵消后，等价于尽量降低结束时的 \(d\)，并少走步。\(s_0\) 上的 \(d\) 对同一条起点是常数，不改变这条起点上的优劣。评测仍看 \((P, F, M, E)\)，不看 \(r_t\)。

算法用带候选掩码的 PPO。裁剪范围 0.2，价值函数拟合回报，优势用回合内归一化。每次更新前收集 2048 步。学习率 \(1 \times 10^{-5}\)。若验证集回放 \(d\) 比模仿阶段的最好结果升高超过 10%，停止更新，退回模仿权重。

\(c\) 和 \(\gamma\) 在第 E 阶段开始时用一组小范围搜索定稿：\(c \in \{0.01, 0.05\}\)，\(\gamma \in \{0.99, 1\}\)。选定后写入实验记录，后续对比沿用同一组。

### 8.4 没有终点时的打分

前两阶段的奖励使用 \(s_T\)。服务上线后请求里没有终点，因此另训一个打分模型，不参与前两阶段的梯度。

样本从会话中构造两类偏好：终点优于起点；终点优于任意一个中间状态。中间状态由该会话的前缀重放得到。模型输入与策略相同的图和文档表摘要，输出一个标量。损失为 \(\mathrm{softplus}(u_{劣} - u_{优})\)。

打分模型的用途是在自主走子时决定是否接受当前文档。接受规则：当前分不低于起点分，且连续两步分数不再上升。这个规则在第 F 阶段用留出会话检验：把会话终点判成优于起点的准确率不低于 90%，才允许接进服务的停止条件。在此之前，服务只提供「给定参考终点」的模式，或由用户逐步确认。

## 9. 评测

验证集冻结之后，下列数字每次实验都报，用同一清单。

| 指标 | 定义 | 阶段 |
|---|---|---|
| 重放通过率 | 事务重放后严格 \(d = 0\) 的会话比例 | A、C |
| 未识别比例 | `unknown` 步数 / 全部事务步数 | B |
| 候选命中率 | 用户动作能在未截断候选里找到的比例 | D |
| 类型准确率 | 动作名正确的步比例 | D |
| 目标准确率 | 动作名和目标 id 都正确的步比例 | D |
| 参数误差 | 位置头的平均毫米误差；词表头的准确率 | D |
| 回放中位 \(d\) | 从 \(s_0\) 由策略走完后，\(d\) 的中位数，并附 \((P,F,M,E)\) 的中位数 | D、E |
| 到达率 | 回放结束时 \(d = 0\) 的图纸比例 | E |
| 终点判别准确率 | 打分模型把 \(s_T\) 判高于 \(s_0\) 的比例 | F |

模仿和强化学习的回放都关闭梯度，候选掩码规则与训练相同。每张验证图纸跑一次，起点是该图纸会话的 \(s_0\)。一张图纸有多条会话时，每条会话各跑一次，按会话数平均。

对照是「不执行任何动作」：其 \(d\) 等于 \(d(s_0, s_T)\)。第 D 阶段要求策略回放的中位 \(d\) 不高于该对照中位数的一半。

## 10. 服务

服务持有仿真的同一套文档加载和动作执行。请求与响应：

```text
POST /edit
请求：文档快照，mode = step | apply
      可选 reference：终点文档。有 reference 时按 d 停止
响应：动作序列，每步含动作名、目标、参数、执行后是否被拒绝
      最终文档快照
      停止原因：save | 步数上限 | 用户停止 | 相对 reference 已到达
```

`step` 每次只给下一步，由调用方决定是否执行。`apply` 连续执行到停止，返回完整序列和最终文档。两种模式的动作定义与训练时相同。

用户在返回结果上继续编辑时，编辑器把「服务输出的文档」当作新的 \(s_0\)，把用户继续编辑后的保存当作新的 \(s_T\)，写成一条新会话。服务内部不保存图纸库；文档由调用方持有，服务只在单次请求的工作目录里保留输入、动作序列和输出，请求结束后可删除。

## 11. 阶段

| 阶段 | 交付 | 验收 |
|---|---|---|
| A | 事务导出含真实旧值；净路径采集；100 条会话 | 100 条全部重放通过，严格 \(d = 0\) |
| B | 映射表、合并规则、`actions.jsonl`；累计 2000 条通过重放的会话 | 未识别比例 < 5%；抽 50 条人工核对，动作名和目标与操作一致 |
| C | 第 7 节四个函数，以及 `replay` | 从 2000 条中抽 100 条，`replay` 与 \(s_T\) 严格一致；同一序列运行两次，文档表一致 |
| D | 模仿训练与第 9 节指标 | 候选命中率 ≥ 95%；回放中位 \(d\) ≤ 不动作对照的一半 |
| E | 从 D 的权重做 PPO | 到达率高于 D；回放中位 \(d\) 不高于 D |
| F | 打分模型，以及无 reference 时的停止规则 | 留出会话上终点优于起点的准确率 ≥ 90% |

A 到 C 是数据和仿真，D 到 F 是模型。D 未达到验收时不开始 E。F 未达到验收时，服务不开启无参考终点的自动停止。

2000 条按一人一天 30 到 50 条估算，约 8 到 14 个工作周。A 的 100 条用来确认导出和重放，不替代 B 的规模。2000 条跑通之后，再根据到达率和未识别比例决定是否增加采集量。

## 12. 前置改造

这些项不完成，对应阶段不能开始。

1. **真实旧值。** `modified` 目前的旧值等于新值。A 阶段改导出，使 `old` 来自事务提交前的值。加载路径继续只使用 `new`。
