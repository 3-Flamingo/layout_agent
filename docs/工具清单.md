# 布局工具接口

日期：2026-10-14

调用方是布局 Agent 的仿真。实现方是田老师的新布局算法。本文是工具清单和接口。11 月按第 4 节交付基本工具，12 月交付局部冲突簇。

一组重分层、一组两侧平衡继续用现有执行，不在本文里新做。接受是决策结束，不是布局工具。

## 1. 调用约定

一次调用只做一件事。坐标用视图局部系，单位毫米，y 轴向上，与视图 JSON 里的 `coords` 一致。标注 `id` 用视图 JSON 里的原 id，不重新编号。

请求：

```json
{
  "tool": "set_linear_side",
  "state": {},
  "args": {}
}
```

`state` 是一份完整视图 JSON，`schema_version` 为 `agent1.1.0`。工具可以只读自己要用的标注、图框和轮廓，但返回时不要带整份新状态，只带改过的标注。仿真负责把这些改动写回原状态，再重新评价。

成功：

```json
{
  "ok": true,
  "tool": "set_linear_side",
  "changed": [],
  "unchanged_ids": []
}
```

`changed` 里每一条只包含该标注被改过的字段，并带 `id` 和 `category`。`unchanged_ids` 是这次读过、但坐标没有改的标注 id。没有读到的标注不要写进这两个数组。

失败：

```json
{
  "ok": false,
  "tool": "set_linear_side",
  "error": {
    "code": "target_not_found",
    "message": "线性尺寸 L3 不在当前视图里",
    "target_id": "L3"
  }
}
```

失败时 `changed` 必须为空。仿真保持调用前的状态。

| `error.code` | 何时返回 |
|---|---|
| `invalid_argument` | 缺字段、类型不对、数值不是有限数 |
| `target_not_found` | `target_id` 在对应数组里不存在 |
| `wrong_category` | id 存在，但不是这个工具能改的类型 |
| `side_not_on_axis` | 翻边目标侧和这条尺寸的轴线不一致，例如左右尺寸被要求改到上侧 |
| `sector_out_of_range` | 扇区不是 0 到 7 |
| `no_geometry_change` | 参数合法，算完后相关坐标与调用前相同 |
| `empty_cluster` | 冲突簇一个 id 都没有 |
| `region_escaped` | 冲突簇改到了入参 id 以外的标注 |

以下字段在所有工具里都保持原值，出现在 `changed` 里即视为实现错误：线性尺寸的 `p1`、`p2`、`value`；直径和半径的 `anchor`。文字框的宽高不改。图框 `legal_bbox` 不改。

斜向线性尺寸只沿当前法向翻边、外推或内收，不把它扭成水平或垂直。法向取 `dir`。`|dir.x| >= |dir.y|` 时轴线是左右，合法侧只有 `L` 和 `R`。否则轴线是上下，合法侧只有 `U` 和 `D`。`dir.x < 0` 为左，`dir.x > 0` 为右，`dir.y > 0` 为上，`dir.y < 0` 为下。

扇区从正右开始，逆时针每 45 度一档：

| 扇区 | 方向 |
|---:|---|
| 0 | 右 |
| 1 | 右上 |
| 2 | 上 |
| 3 | 左上 |
| 4 | 左 |
| 5 | 左下 |
| 6 | 下 |
| 7 | 右下 |

引线终点相对锚点的方向应落在该扇区中心正负 22.5 度以内。

## 2. 基本工具

六个工具都在 11 月交付。线性分组不改坐标。翻边、外推、内收只改一条线性尺寸。改扇区只改一条直径或半径。文字滑动两者都可以。

### 2.1 线性分组 `group_linears`

决策前调用，用来知道哪些线性尺寸是同一方向、现在在哪一侧。不改任何坐标。成功时 `changed` 为空，分组结果放在 `groups`。

方向差在 1 度以内的线性尺寸归为同一组。组号按方向角从小到大编号，从 `g0` 起。组内 id 按测量跨度从大到小排列。

`args` 为空对象。

```json
{
  "tool": "group_linears",
  "state": {},
  "args": {}
}
```

```json
{
  "ok": true,
  "tool": "group_linears",
  "changed": [],
  "unchanged_ids": ["L1", "L2", "L3"],
  "groups": [
    {
      "group_id": "g0",
      "axis": "horizontal",
      "members": [
        { "id": "L1", "side": "L" },
        { "id": "L2", "side": "R" }
      ]
    }
  ]
}
```

`axis` 为 `horizontal`、`vertical` 或 `angled`。视图里没有线性尺寸时，`groups` 为空数组，仍然 `ok: true`。

### 2.2 单条翻边 `set_linear_side`

把一条线性尺寸换到本轴线的对侧。尺寸线参考点 `point`、法向 `dir`、文字中心 `text_point` 可以改。测量点不动。同一侧已经在目标侧上的其它线性尺寸，如果和它的投影区间重叠，只允许为了让开而调整层距，这些尺寸也要出现在 `changed` 里。不在目标侧上的尺寸不动。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_id` | string | 线性尺寸 id |
| `side` | `L` `R` `U` `D` | 目标侧，必须在该尺寸的轴线上 |

```json
{
  "tool": "set_linear_side",
  "state": {},
  "args": { "target_id": "L3", "side": "R" }
}
```

```json
{
  "ok": true,
  "tool": "set_linear_side",
  "changed": [
    {
      "id": "L3",
      "category": "linear",
      "point": { "x": 128.0, "y": 40.0 },
      "dir": { "x": 1.0, "y": 0.0 },
      "text_point": { "x": 128.0, "y": 40.0 }
    }
  ],
  "unchanged_ids": ["L1", "L2"]
}
```

目标侧就是当前侧时返回 `no_geometry_change`。不要把同侧请求偷偷变成外推。外推用第 2.3 节。

### 2.3 单条外推 `nudge_linear`

把一条线性尺寸沿当前朝外的法向再推远。`distance_mm` 是相对当前位置的外推量，不是离零件的绝对距离。默认 4 毫米，允许 1 到 20 毫米。只改这一条的 `point`、`dir`、`text_point`。其它标注 id 不得出现在 `changed` 里。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_id` | string | 线性尺寸 id |
| `distance_mm` | number | 向外推的距离，省略时为 4 |

```json
{
  "tool": "nudge_linear",
  "state": {},
  "args": { "target_id": "L3", "distance_mm": 4 }
}
```

```json
{
  "ok": true,
  "tool": "nudge_linear",
  "changed": [
    {
      "id": "L3",
      "category": "linear",
      "point": { "x": 18.0, "y": 40.0 },
      "dir": { "x": -1.0, "y": 0.0 },
      "text_point": { "x": 18.0, "y": 46.0 }
    }
  ],
  "unchanged_ids": []
}
```

外推之后，尺寸线到被测边中点的距离应比调用前大约增加 `distance_mm`，允许 0.5 毫米误差。方向应仍朝外，不能推回零件内侧。

### 2.4 单条内收 `pull_linear`

把一条线性尺寸沿当前朝外的法向收回，靠近被测边。`distance_mm` 是相对当前位置的内收量。默认 4 毫米，允许 1 到 20 毫米。只改这一条的 `point`、`dir`、`text_point`。其它标注 id 不得出现在 `changed` 里。

内收停在被测边外侧。尺寸线到被测边中点的剩余距离不得小于 8 毫米，也不得越过测量点进入零件内侧。请求的距离会越过这条界线时，只收到界线上；已经在界线上或更近时，返回 `no_geometry_change`。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_id` | string | 线性尺寸 id |
| `distance_mm` | number | 向内收的距离，省略时为 4 |

```json
{
  "tool": "pull_linear",
  "state": {},
  "args": { "target_id": "L3", "distance_mm": 4 }
}
```

```json
{
  "ok": true,
  "tool": "pull_linear",
  "changed": [
    {
      "id": "L3",
      "category": "linear",
      "point": { "x": 22.0, "y": 40.0 },
      "dir": { "x": -1.0, "y": 0.0 },
      "text_point": { "x": 22.0, "y": 46.0 }
    }
  ],
  "unchanged_ids": []
}
```

内收之后，尺寸线到被测边中点的距离应比调用前大约减少实际收进的距离，允许 0.5 毫米误差。侧向不变，仍在原来的左、右、上或下。

### 2.5 单条改扇区 `set_radial_sector`

把一条直径或半径的引线放到指定扇区。`path` 的终点改到该方向上。引线长度保持当前长度；当前长度小于 1 毫米时用 24 毫米。长度限制在 12 到 30 毫米。锚点不动。文字中心与引线终点一致。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_id` | string | 直径或半径的 id |
| `sector` | integer | 0 到 7，见第 1 节 |

```json
{
  "tool": "set_radial_sector",
  "state": {},
  "args": { "target_id": "D1", "sector": 2 }
}
```

```json
{
  "ok": true,
  "tool": "set_radial_sector",
  "changed": [
    {
      "id": "D1",
      "category": "diameter",
      "path": [
        { "x": 40.0, "y": 30.0 },
        { "x": 40.0, "y": 54.0 }
      ],
      "text_point": { "x": 40.0, "y": 54.0 }
    }
  ],
  "unchanged_ids": []
}
```

目标扇区与当前扇区相同，返回 `no_geometry_change`。不要私自改到别的扇区。

### 2.6 文字滑动 `slide_text`

把一条尺寸的文字沿尺寸线方向移动。`offset_mm` 为正时，文字沿尺寸线从第一测量点指向第二测量点的方向移动；为负时反向。线性尺寸移动 `text_point`。直径和半径移动 `path` 终点在引线方向上的投影位置，锚点不动，引线方向不变。省略 `offset_mm` 时为 4。允许范围是 -30 到 30 毫米，且不能为 0。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_id` | string | 线性尺寸、直径或半径的 id |
| `offset_mm` | number | 沿尺寸线的位移 |

```json
{
  "tool": "slide_text",
  "state": {},
  "args": { "target_id": "L3", "offset_mm": 6 }
}
```

```json
{
  "ok": true,
  "tool": "slide_text",
  "changed": [
    {
      "id": "L3",
      "category": "linear",
      "text_point": { "x": 46.0, "y": 22.0 }
    }
  ],
  "unchanged_ids": []
}
```

`point` 和 `dir` 不变时不要放进 `changed`。文字中心的位移长度应等于 `|offset_mm|`，允许 0.5 毫米误差。

## 3. 方法工具

### 3.1 局部冲突簇 `repair_conflict_cluster`

12 月交付。决策已经知道哪些标注互相冲突，把这些 id 交给工具。工具只在这些 id 上重新摆放，使可见硬冲突减少。可见硬冲突指文字重叠、穿尺寸线、碰引线、出框、进零件、压轮廓。

| 字段 | 类型 | 含义 |
|---|---|---|
| `target_ids` | string[] | 1 到 12 个标注 id，可混合线性尺寸、直径、半径 |
| `problems` | string[] | 希望消掉的问题代码，取自标注规范里的可见硬冲突或软问题 |

```json
{
  "tool": "repair_conflict_cluster",
  "state": {},
  "args": {
    "target_ids": ["L2", "L3", "D1"],
    "problems": ["text_overlap", "text_cross_line"]
  }
}
```

```json
{
  "ok": true,
  "tool": "repair_conflict_cluster",
  "changed": [
    {
      "id": "L3",
      "category": "linear",
      "point": { "x": 20.0, "y": 36.0 },
      "dir": { "x": -1.0, "y": 0.0 },
      "text_point": { "x": 20.0, "y": 36.0 }
    },
    {
      "id": "D1",
      "category": "diameter",
      "path": [
        { "x": 40.0, "y": 30.0 },
        { "x": 64.0, "y": 30.0 }
      ],
      "text_point": { "x": 64.0, "y": 30.0 }
    }
  ],
  "unchanged_ids": ["L2"]
}
```

`changed` 与 `unchanged_ids` 的并集必须等于 `target_ids`，不能多也不能少。入参以外的标注有坐标变化时返回 `region_escaped`。算完后这些 id 之间的所列 `problems` 没有减少，并且坐标也没有变化时，返回 `no_geometry_change`。有坐标变化但问题没减少，仍然 `ok: true`，由仿真的评价决定这一步要不要留下。

簇内一条线性尺寸的摆放方式与第 2.2、2.3、2.4、2.6 节相同：只改侧向、层距和文字位置。一条直径或半径与第 2.5、2.6 节相同：只改扇区和文字沿引线的位置。

## 4. 交付顺序

| 时间 | 工具 | 完成标准 |
|---|---|---|
| 11 月第 1 周 | `group_linears`、`set_linear_side`、`nudge_linear`、`pull_linear` | 各带 3 个固定样例。样例包含请求、返回、以及不该变的 id。内收样例要包含收到 8 毫米界线就停止的情况 |
| 11 月第 2 周 | `set_radial_sector`、`slide_text` | 同上。六个基本工具都能被仿真选中并执行 |
| 11 月第 3 周 | 上述六个 | 改掉接入后出现的错坐标、没生效的调用 |
| 11 月第 4 周 | 上述六个 | 接口不再改，供轨迹采集使用 |
| 12 月第 2 周 | `repair_conflict_cluster` | 3 个样例。入参以外的标注坐标与调用前一致 |
| 12 月第 3 周 | `repair_conflict_cluster` | Agent 能选中并执行 |
| 12 月 31 日 | 全部七个 | 版本固定。其后只改错坐标和写回失败，不加第八个工具 |

每个样例用真实视图 JSON，放在 `data/evalsys/tool_fixtures/<tool>/` 下，包含 `request.json`、`response.json` 和一句说明改了什么。样例里的数字必须能由该工具从请求算出来，不手写一个对不上的返回。
