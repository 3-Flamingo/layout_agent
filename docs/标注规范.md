# 标注规范

日期：2026-10-10

标注人：庚池。规范维护：陈震。操作顺序见 [标注流程](标注流程.md)。

文件为 JSONL，一行一条，UTF-8。路径相对于 `data/evalsys/annotate_2026q4/`。视图 JSON 由陈震导出，标注不改几何。

## 1. 共用约定

### 1.1 视图 JSON

格式与现有 `LayoutState` 相同，`schema_version` 为 `agent1.1.0`。合格条件：

- 坐标在视图局部系，单位毫米，y 轴向上。
- `view.bbox` 或 `view.legal_bbox` 有 `min`、`max`。
- `linears`、`diameters`、`radials` 至少有一类非空。
- 线性尺寸含 `id`、`p1`、`p2`、`dir`、`point`。直径和半径含 `id`、`anchor`、`path`。
- 评价器能读入。读入失败则整条退回。

`view_key` 写成 `{solution_id}/{view_uuid}`。同一张生产视图的不同布局用不同 `state_id`，`view_key` 可以相同。偏好对左右两侧的 `view_key` 必须相同。

### 1.2 标签代码

看工程图预览。一张图可多选。

可见硬冲突。出现任意一项时，`acceptable` 必须为 false：

| 代码 | 图上看到的现象 |
|---|---|
| `text_overlap` | 两个尺寸文字的外框互相压住 |
| `text_cross_line` | 尺寸文字压住另一条尺寸的尺寸线（带箭头的那一段） |
| `text_touch_leader` | 尺寸文字压住箭头短线、折线，或直径、半径的引线 |
| `out_of_frame` | 尺寸文字跑出视图图框 |
| `text_in_part` | 尺寸文字中心落在零件轮廓内部 |
| `text_on_contour` | 尺寸文字压在零件轮廓线上 |

软问题。可以和 `acceptable = true` 同时存在：

| 代码 | 图上看到的现象 |
|---|---|
| `overcrowd` | 尺寸明显堆在同一侧，对侧空着 |
| `radial_clash` | 多条直径或半径的引线、文字互相挤在一起 |

只作记录。不改变 `acceptable`，也不写入验收图的 `expected`：

| 代码 | 图上看到的现象 |
|---|---|
| `dim_cross` | 两条尺寸线彼此相交 |
| `text_touch_extension` | 尺寸文字擦到尺寸界线。界线是从被测点连到尺寸线两端的那段 |

没有可见硬冲突、也没有软问题时，`problems` 为 `[]`，`acceptable` 为 true。`comment` 没有内容就写空字符串。`annotator` 固定为 `庚池`。

### 1.3 退回

整条退回，不计入当月数量：

- 视图 JSON 打不开，或评价器报错。
- 没有线性尺寸、直径、半径。
- 预览图和 JSON 不是同一布局。
- `acceptable` 为 true，但 `problems` 里仍有可见硬冲突。
- 偏好对两侧 `view_key` 不同，或看不出哪一侧更好仍写了 `prefer`。
- 验收图的 `expected` 为空，或写了 `dim_cross`、`text_touch_extension`。
- 记录落在已冻结评测图上。
