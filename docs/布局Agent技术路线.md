# 布局 Agent 技术路线

日期：2026-10-12

周期：2026 年 10 月至 12 月。12 月 31 日前完成落地，能在真实视图上改标注并写回图纸。

三人分工：陈震负责架构、训练和落地；庚池负责标注；田老师用新的布局算法做出可调用的结果，并拆成工具。

## 1. 目标

12 月底要同时有三样东西：

- Agent 在一张视图上跑完一轮：评价、选工具、执行、再评价、停止。
- 至少 20 张真实视图通过 `LayoutApplyPatch` 写回 drawing-2d。
- 200 张验收图有对照：原图、现有规则决策、这一版 Agent 的可见硬冲突条数和公式代价。

覆盖线性尺寸、直径和半径。角度、引线、粗糙度不在这一版里。

决策有两条候选。策略在留出视图上的硬违规消除率、最终公式代价和步数都超过规则和贪心时，用策略。有一项没有超过，用贪心在合法工具里选公式代价更低的动作。两条都能完成上面的落地。

成功标准：验收图上可见硬冲突条数下降的比例不低于 60%，且中位条数不高于现有规则决策器。可见硬冲突指文字重叠、穿尺寸线、碰引线、出框、进零件、压轮廓。尺寸线相交和文字蹭界线单独统计。

## 2. 路线

```text
生产视图 JSON
    │
    ├─ 标注：问题标签 / 偏好对 / 验收期望
    │
    ▼
仿真环境
    │  评价（现有规则）
    │  决策（贪心或策略）
    │  工具（基本工具、局部冲突簇）
    │  再评价、调度、停止
    ▼
LayoutApplyPatch → drawing-2d 写回
```

已有能力直接沿用：规则评价、执行与调度、公式奖励、残差评分器、578 对偏好和冻结评测、行为克隆与掩码 PPO 的训练程序。残差评分器继续使用现有权重，这一版不重新训练。学习项系数 β 保持 0，逐步奖励用公式项。

公式奖励看一步前后的硬违规量和软代价：硬违规下降、软代价下降、硬违规刚刚清掉的奖励，再减去每步惩罚和无效动作惩罚。选择接受时，没有硬违规给正奖励，仍有硬违规给负奖励。

策略网络只替换决策。它在合法工具调用里选一个。评价、执行、调度保持规则。基本工具一次改一条标注。局部冲突簇一次改一小块区域里互相冲突的标注，区域外不动。整组重分层和两侧平衡在这一版仍用现有执行。

## 3. 数据

庚池大约每 5 个工作日标 200 张。每张都有可评价的视图 JSON。三个月合计大约 2160 张。已有的 578 对偏好、170 对测试、冻结的 136 张和 80 对继续作离线对照。12 月的 200 张验收图不进入轨迹采集，也不用来挑选 checkpoint。

| 月份 | 大约张数 | 构成 |
|---|---:|---|
| 10 月 | 400 | 问题标签。第 2 周规范定稿后先试标，第 3、4 周各 200 张 |
| 11 月 | 840 | 约 640 张问题标签，100 对偏好（200 张）。问题标签优先硬冲突明显的图 |
| 12 月 | 920 | 约 520 张问题标签，100 对偏好（200 张），200 张验收 |

问题标签可多选：文字重叠、穿尺寸线、碰引线、出框、进零件、压轮廓、单侧过密、直径半径打架，以及可接受。尺寸线相交、文字蹭界线可以记下。偏好对标明哪一侧更好。验收图写明希望消掉的问题。字段和文件见标注规范。

仿真轨迹由程序生成。有可见硬冲突的视图进入采集，采集用规则、贪心和集束搜索。标成可接受的视图只用来学接受并停止。

## 4. 工具

10 月把工具分成基本工具和方法工具，写清入参、出参和报错。工具清单见 [工具清单](工具清单.md)。工具输入是视图 JSON 和参数，输出是改过的标注坐标。工具不渲染、不写 CAD。

11 月田老师从新布局算法里拆出基本工具，一次改一条标注，仿真改为调用这些工具。12 月再交局部冲突簇，一次改一小块区域。算法内部以田老师的新算法为准，接口以 10 月定稿为准。
